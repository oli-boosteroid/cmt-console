# CMT Console v3.0

Большое обновление консоли: новый внешний вид, переделанные чаты и админка, новые функции по Jira, Feedback и публичной странице Known Issues, ускорение и экономия запросов.

## Новый внешний вид

- Три темы в стиле нашей админки: **Dark** (тёмная админки), **Glassy** (стеклянная тема админки) и **Light** (светлая админки). Переключение кнопкой в шапке: Dark → Glassy → Light.
- Левое меню во всех темах как в Glassy: мелкие моноширинные подписи групп, компактные пункты.
- Во всех трёх темах одинаковая раскладка: плавающее меню слева, плавающая верхняя панель, отдельные панели с отступами. Отличаются только цвета. Скругления углов во всех темах как в Glassy.
- Glassy повторяет эффекты админки: медленно двигающийся цветной фон (приглушён), стекло с бликом и тонким кантом, «жидкие» кнопки. При включённом в системе уменьшении движения или прозрачности фон не двигается и стекло становится плотным.
- Новый набор иконок в едином стиле, со срезанными углами. Отдельные иконки у Game Cards, New Games Testing и Add Testing Session (геймпад).
- Раздел **Game Testing переименован в New Games Testing**.
- Списки To-Do, Monitor, Maintenance и Reply log стали таблицами с заголовками колонок. На телефоне строки превращаются в карточки с подписями.
- Загрузка показывается «скелетоном» вместо надписи Loading.
- Полосы прокрутки тонкие и без стрелок.
- Поля поиска: одна рамка без серого прямоугольника внутри (окна поиска, Known Issues, быстрый поиск Ctrl+K).

## Чаты (Reddit, Discord, Telegram, Posts)

- **Очередь слева:** строка в две линии (имя и время, под ним превью), короткое время («25m», полное при наведении), разделители по дням («Today», «19 Nov»). Цветных полос слева больше нет: статус показан точкой у времени.
- **Окно чата:** шапка в одну строку (имя, тема, статус, иконки действий). Лента прижата к полю ответа. Разделители дат в переписке. Сообщения подряд от одного автора идут одним блоком.
- **Наши ответы справа**, сообщения пользователя слева.
- **Translate** появляется при наведении на сообщение (на телефоне видна всегда).
- **Поле ответа:** одна рамка, кнопки внутри, поле растёт вместе с текстом.
- **Правая панель стала вкладками:** Tags, Linked tickets, Identity, Maintenance, Gaming Proposal, Notes, Shift handoffs, All. Выбор запоминается.
- Меню статусов в цвете темы (раньше открывалось белым).

## Inbox

- To-Do прокручивается до конца (раньше список обрезался снизу).
- Цифры на плитках без декоративных полос.
- Вкладки To-Do / Monitor / Team на телефоне в одну строку.
- В колонке When дата и «сколько назад» в две строки: длинное время («18 Nov 05:43», «1d ago») всегда помещается, не сжимая Subject и From. Убрана лишняя линия над таблицами To-Do, Monitor и Maintenance.

## Меню

- Раздел **Actions переименован в Quick Actions** и перенесён в группу Workspace, сразу под Inbox. У заголовков категорий убраны иконки.
- **Get Sessions.** Если User ID вводится вручную (Create Ticket, Urgent Request, Link Ticket), появляется кнопка Get Sessions, и только по ней консоль идёт в админку за сессиями. Если User ID известен из чата, сессии грузятся сразу, как раньше. В Urgent Request появилось отдельное поле User ID.

## Admin

- Админка разбита на вкладки: **Team, Known Issues, Sheets, Reddit, Discord, Automation, Content, Data, Reports**. Все прежние панели на месте, выбранная вкладка запоминается.
- Участники на вкладке Team идут сеткой карточек.

## Jira

- **Подсказки в Link Jira Ticket.** При наборе проблемы («black screen») или номера («14150», «SO-142») показываются уже созданные тикеты, в первую очередь из Backlog. Название тикета видно полностью, после выбора оно же показывается в подтверждении. В этом окне только тикеты SO: URG здесь не показываются (у них свой поток Create Urgent), но номер URG, вписанный полностью, всё равно можно привязать. Номера тикетов больше не переносятся на две строки. Бот хранит названия тикетов: из Slack (#jira-notifications), при создании тикета и из лёгкой сверки с Jira.
- **L1 In Progress → «Update the user».** Когда тикет SO переходит в L1 In Progress, бот находит в комментариях нашей команды User ID, ID сессий и ссылки на чаты, а также чаты, привязанные к тикету.
  - В To-Do появляется отдельная карточка на каждого пользователя или чат. User ID ведёт в профиль, Discord и Reddit ведут в чат.
  - Тем, кто на смене, приходит одно уведомление со всеми пользователями сразу. Новый тип уведомлений в настройках: «Ticket in L1 In Progress (users to update)».
  - **Защита от случайной смены статуса:** бот ждёт минуту и проверяет статус ещё раз. Если тикет уже ушёл из L1, ничего не происходит.
  - **Done не меняет статус тикета.** Если пользователь был оставлен в нашем комментарии, Done отвечает «Передано» под этим комментарием (упоминание автора и ссылка на комментарий). Для чатов, найденных по привязке, комментарий не пишется. Если Jira не приняла комментарий, карточка не закрывается.
- **Link Ticket (Quick Actions и из чата).** Форма: тикет (подсказки только по SO), ссылка на чат с юзером (из чата подставляется сама), User ID, Session info, текст (необязательно). Нужно указать User ID или сессию. В тикет уходит один комментарий в привычном формате: User ID, сессии, текст, ссылка на чат, без лишних подписей. Чат, если он есть в консоли, тоже привязывается, а пользователь попадёт в To-Do, когда тикет дойдёт до L1 In Progress.
- В Events колонка **Time** стоит первой.
- Последние сессии пользователя (Add Testing Session и другие формы) показывают **лаунчер**: Steam, Epic, Xbox.

## Known Issues в консоли

- В предложении и при добавлении проблемы админом можно указать несколько игр, по одной в строке. При одобрении для каждой игры создаётся своя строка в таблице, повторы убираются. В списке предложений игры показаны отдельными метками.

## Уведомления админам

- **Админские уведомления (новый Feedback, заявки на отпуск или больничный, предложения Known Issues) приходят админам всегда:** и вне рабочих часов, и во время Testing, и в отпуске. Раньше они глушились вместе с обычными, поэтому в отпуске перестали приходить в Telegram. В настройках уведомлений под Admin alerts есть пометка об этом.

- Новое уведомление **Known issue suggested**: когда кто-то предлагает проблему для Known Issues (из консоли или с публичной страницы), админам приходит уведомление в колокольчик и в подключённые каналы. Ссылка ведёт сразу на вкладку Admin > Known Issues. Отключается в настройках уведомлений.

## Feedback

- Новая панель отзыва в формате админки: категории **Bug, Suggestion, Question** плитками, счётчик символов 0 / 2000, кнопка во всю ширину, ссылка «All my feedback».
- **Свой отзыв можно отредактировать** (кнопка Edit, пометка «edited»). Статус и ответ по-прежнему меняет только админ.
- **Ответ админа редактируется кнопкой Edit на самом ответе.** Поле ответа видно, только пока ответа нет, а не висит под каждым отзывом. Edit у текста отзыва теперь только у автора.

## Публичная страница Known Issues

- Новый дизайн в тёмной теме консоли.
- **Кнопка Feedback**: отзыв со страницы приходит в Feedback консоли с подписью «Known Issues page», админу приходит уведомление. Есть защита от спама.
- **Игры без проблем тоже находятся поиском** (блок «Other games»), и для них можно сразу предложить проблему.
- **Поиск игр в окне предложения проблемы** с подсказками из Game List и меткой лаунчера.
- **Одна проблема сразу для нескольких игр.** В окне предложения игры добавляются плашками (из Game List или как написано, через Enter), лишнюю можно убрать крестиком.
- Исправлено: при фильтре не скрывались неподходящие строки.

## Скорость и обновление без F5

- Консоль больше не скачивает заново все списки сразу после открытия: раньше первая фоновая проверка перекачивала около 30 списков у каждого оператора при каждом входе.
- Настройки только для Admin грузятся при открытии Admin, а не у всех при старте.
- Events, Bans и Facebook обновляются сами (раньше висели до перезагрузки).
- Убраны дублирующиеся запросы меток Jira.
- Облачная админка: поиск пользователя, владелец сессии и повторный Refresh сессий берутся из кэша, лишние запросы в облако не уходят.
- По замерам на стенде: при открытии 57 запросов вместо 68, в простое после загрузки 9 запросов за 35 секунд вместо примерно 45. Новые сообщения, тикеты и заметки появляются сами за 0.4-7 секунд.

## Скорость на телефоне

- Длинные списки (чаты, To-Do, Monitor и другие таблицы) не просчитывают строки за пределами экрана: список из 1300 диалогов строится примерно в 3,5 раза быстрее.
- На телефоне убрано размытие у панелей и прилипающих заголовков (они и так почти непрозрачные), в Dark и Light размытия на телефоне нет совсем. В Glassy на телефоне фон не двигается, стекло остаётся.
- Невидимая полоса загрузки больше не анимируется постоянно.
- Окна форм (Create Ticket, Urgent Request, Link Ticket и другие) на телефоне открываются на весь экран, а не сдвинутым узким окном.
- Бот пишет в индекс тикетов Jira только изменившиеся тикеты: раньше каждые 10 минут переписывал все 200 найденных.
- Плашка «Test mode» на телефоне в две строки, полный текст по нажатию.

## Исправления

- Всплывающие сообщения (toast) снова читаются: в общем стиле тем текст был цвета фона, а ошибки потеряли красный цвет.
- Битые картинки в чатах снова заменяются подписью (раньше это блокировала политика безопасности браузера).
- Свёрнутое меню: иконка Customize menu больше не переворачивается.
- Телефон: в списках чатов (Reddit ModMail, Posts, Discord) под списком больше не висит пустое окно «Select a conversation», список снова на весь экран. На экране Details больше не показывается чат.
- Левое меню больше не прыгает наверх при открытии раздела: прокрутка сохраняется.
- Шапка чата на узкой панели больше не обрезает статус. Статус «Waiting on user» больше не обрезается в шапке чата.
- Служебный токен бота сохранил права на изменение статуса и ответа в Feedback.
- Game Cards: после загрузки консоли больше не мелькают демо-карточки (Hades II, Split Fiction). Пока карты грузятся, показывается загрузка.
- Game Cards, Add game: новая карта предлагается, даже если игру уже добавляли на другой платформе (например, Football Manager 27 для Xbox на прошлой неделе больше не скрывает Steam-версию).
- Трейлеры в картах: сначала Launch / Release трейлер, потом Official, потом остальные. Демо, пред-заказ, DLC, обновления, бета и подобные трейлеры не берутся, каналы PlayStation (PS5/PS4) тоже. Для малоизвестных игр (меньше 10 000 отзывов в Steam) сначала ищется трейлер на IGN, GameTrailers или GameSpot. Трейлер берётся только с канала от 100 тысяч подписчиков и с 10 тысяч просмотров, иначе в карте остаётся ссылка на поиск YouTube, как раньше, и трейлер ищется вручную.
- Add game: игры с апострофом в названии (John Carpenter's Toxic Commando) снова находятся в Steam. Раньше поиск находил только DLC и саундтрек. Сама игра теперь всегда стоит первой в списке.
- Game Cards: «Download images» снова работает для игр с эмодзи в названии (например, Finals Week ✍️). Раньше такое имя ломало ответ сервера, и браузер скачивал пустой .txt.
- Game Cards: под Related Apps появилась подпись с ID игр из Game List (по порядку, через запятую). ID подтягиваются сами после заполнения поля, «?» значит, что игры нет в Game List. Версия с (Xbox) получает ID Xbox-строки, без пометки ID Steam-строки.
- Исправлена причина «внезапных» непрочитанных: после загрузки консоли заигноренные посты, ручные статусы чатов (Done, In progress, Waiting) и теги не сохранялись для следующих обновлений. Когда приходил новый пост или сообщение, список пересобирался без них: заигноренные посты возвращались в No reply (те самые 33), старые тикеты Discord снова требовали ответа после отправки сообщения, теги ставились «через раз». Помогала только перезагрузка или чужое действие с флагами. Теперь всё это сохраняется, в том числе сразу после своего действия.
- Если при загрузке консоли не загрузились флаги постов, статусы или теги (например, во время деплоя), они подтянутся при следующем опросе, а не останутся пустыми до изменения.
- Свои действия больше не откатываются на экране обновлением, которое началось раньше них: «прочитано», «отвечено» в ModMail и игнор в Telegram держатся поверх ответа сервера, пока сервер их не отдаст.
- Закрытые тикеты Discord из архива, поиска по архиву и истории в Profile 360 теперь тоже показывают ручной статус и теги.
- Отметка «no tag» и привязка Jira к посту тоже переживают обновление списка.
- Linked tickets в боковой панели: рядом с номером тикета виден его текущий статус в Jira.
- Окна (Customize menu и все остальные): галочка или стрелка внизу списка больше не отбрасывает прокрутку в начало.
- Maintenance: «Playgrounds 1» и другие вкладки с числом больше не переносят число на вторую строку.
- Game Cards: убран лишний отступ над кнопкой Add game.
- Quick Actions: иконка и текст в каждой плитке выровнены по центру по высоте.
- Телефон: чат открывается внизу, на последних сообщениях (раньше открывался сверху). После отправки и при возврате из Details чат тоже показывает последние сообщения.
- Телефон: кнопка Chat на экране Details снова возвращает в чат.
- Телефон: шапка чата больше не прозрачная, сообщения не просвечивают под ней при прокрутке.
- Смена темы больше ничего не сдвигает: в Glassy кнопки шапки и заголовки страниц стоят там же, где в Dark и Light.
- Новый дизайн Black: чисто чёрный, без серого (как чёрная тема Discord). Это тот же Dark, только на чёрном: чёрные панели с тонкой белой линией, акценты те же. Размеры и отступы те же, что в Dark, при переключении ничего не сдвигается.
- Кнопка смены темы в шапке теперь открывает окно «Change design»: карточки Dark, Black, Glassy и Light с мини-превью и описанием. Дизайн выбирается кликом и применяется кнопкой Save, Cancel ничего не меняет. В поиске (Ctrl+K) пункт тоже называется «Change design».
- Телефон (Android Chrome): шапка чата (имя, статус, кнопки) больше не просвечивает, текст сообщений при прокрутке уходит под неё, а не рисуется поверх.
- User IDs from files: ID 0 в файле теперь значит «аккаунт удалён». Такой адрес не получает ID 0, при миграции у записи стирается email и ставится статус «Account deleted». Ни бот, ни консоль больше не спрашивают облачный API про эти адреса. Если один адрес в файле встречается и с 0, и с настоящим ID, берётся настоящий ID. В панели видно, сколько удалённых аккаунтов в карте и в базе.
- Добор оставшихся емейлов через облачный API ускорен: один запрос в 2 секунды (30 в минуту) вместо 3 в час. Емейлы, которые уже есть в загруженных файлах, запрос не тратят. Если за последнюю минуту уже ушло 40 запросов (операторы ищут пользователей), добор ждёт, так что лимит API 60 в минуту не превышается. Упор в лимит больше не помечает запись ошибкой: она просто повторяется позже. Общий потолок бота поднят до 50 запросов в минуту и 3000 в час.
- User IDs from files: .json читается, даже если в нём нет внешних фигурных скобок или в конце стоит лишняя запятая (ручная выгрузка).
- User IDs from files: кнопка «Add found emails to a file». Выбираешь файл (например, список Ромы), консоль отдаёт этот же файл с дописанными в конец адресами, для которых бот нашёл ID через API (в том же формате {"email": id}). «Download found only» скачивает только найденные ботом. Если адрес уже есть в файле, остаётся значение из файла. Консоль ничего при этом не сохраняет.
- User IDs from files, Preview migration: теперь видно, из чего состоят записи «с email» (настоящие адреса, сколько разных, сколько из них есть в файлах, session ID, числа, мусор, не расшифровываются) и сколько ID в карте из файлов. Совпадение ищется и по сохранённому хэшу, и по хэшу, пересчитанному из самого адреса, так что запись со старым хэшем тоже найдётся.
- Discord Forum: фильтры форумов и тегов, которые не помещаются в одну строку, больше не превращаются в растянутый овал, теперь это аккуратная скруглённая плашка. Однострочные фильтры выглядят как раньше.
- Discord Forum: шапка поста переделана. Заголовок идёт на всю ширину и не сжимается чипами, под ним статус, форум и теги, кнопка «Open in Discord» справа по центру. Пустой чип форума больше не показывается.
- Телефон, Discord Forum: открывается список постов, а не пустое окно «Select a forum post». Кнопка «назад» из поста возвращает в список форума, а не в тикеты.
- Добор User ID через облачный API теперь понимает и session ID, сохранённые вместо email (форма Discord принимает оба): бот находит владельца сессии через API сессий. Уже пропущенные session ID берутся ещё раз, по одному запросу на каждый, с тем же темпом и лимитом. В логе миграции «left» теперь показывает реальный остаток (раньше из-за ошибки в подсчёте там был 0).
- Емейлы больше нигде не сохраняются: упоминания в Discord хранят только User ID, сообщения Telegram получают User ID вместо копии емейла, старое добавление емейла и сохранение емейла из custom issue на сервере бота отключены.
- Admin > Data: кнопка «Remove all emails» (сначала «Preview cleanup of all emails» с точными цифрами). Записи справочника с User ID оставляют только ID, записи без User ID удаляются; из упоминаний Discord, сообщений Telegram, отслеживаемых пользователей Jira, заметок Reddit и банов емейлы убираются; карта email -> User ID удаляется; добор через API выключается. Действие необратимо, запускать после добора и выгрузки файла.
- Получатели URG (To-Do «URG - Review»): вместо емейла из тикета хранится и показывается «User ID N». Если в тексте тикета есть User ID, берётся он; если только емейл, бот находит ID через админку; адрес не сохраняется.
- Рассылка о техработах по email: адрес больше не остаётся в очереди действий консоли после отправки, а в логе и в сообщении оператору в Slack он замаскирован.
- Бот больше не дописывает хэши емейлов в карту email -> User ID (её удаляет «Remove all emails»).
- «Remove all emails» дополнительно чистит получателей URG и адреса в очереди действий консоли. Значения «User ID N» в упоминаниях Discord, сообщениях Telegram и отслеживаемых пользователях Jira сохраняются обычным текстом, чтобы читаться и после отключения шифрования.
- Бот: Telegram-бот консоли (вкладка Telegram) больше не умирает насовсем, если при старте Telegram не ответил (таймаут сети на VM). Он пробует снова через 10 секунд, потом реже, до раза в 5 минут. Длинные ошибки в Slack-канал логов больше не теряются: раньше длинный traceback превышал лимит блока Slack (invalid_blocks), теперь середина обрезается, начало и конец видны.
- «Remove all emails»: адреса в упоминаниях Discord, сообщениях Telegram, отслеживаемых пользователях Jira и получателях URG теперь сначала превращаются в «User ID N», если ID уже известен (из файла Ромы или из справочника, без запросов в админку). Стираются только те, для которых ID не нашёлся. Preview показывает отдельно, сколько станет User ID и сколько будет удалено; для удаляемых записей справочника видно, что в них лежит (емейл, список Facebook или только хэш).

## Порядок и надёжность (аудит 21.11)

- Slack «Create Jira Ticket» и «Create Urgent Request» теперь создают тикет той же функцией, что и консоль. Емейл пользователя больше не попадает в Jira ни в ссылке на админку, ни в комментарии «Additional user»: вместо него стоит User ID со ссылкой на сессии. Если у адреса нет аккаунта, Slack, как и консоль, не создаёт тикет и пишет причину в личку.
- Уведомление Slack «Ticket moved to CM In Progress»: вместо адресов из комментариев Jira показываются User ID, адреса в последнем комментарии тоже заменяются.
- Двойной клик или повторная отправка одного и того же действия в течение 15 секунд больше не выполняются дважды (два тикета, два ответа пользователю). Консоль возвращает уже поставленное действие.
- Действие, которое бот выполнял в момент перезапуска, больше не висит в статусе «processing»: при старте оно помечается ошибкой с подсказкой проверить, прошло ли оно. Повторно оно не запускается, чтобы не отправить ответ дважды.
- Vacation / Sick leave: если два админа одобряют одну заявку одновременно, срабатывает только одно решение. Баланс списывается один раз, календарь и сообщение сотруднику не дублируются.
- Привязка Jira к Discord-тикету из консоли теперь требует права на раздел Discord, как и остальные действия Discord.
- SLA-напоминания больше не приходят по отложенным Discord-тикетам (Postpone), пока пользователь не напишет снова. Раньше проверялось поле, которого нет.
- Бот, Discord: фоновая проверка отложенных тикетов разбита на независимые шаги. Ошибка в одном шаге больше не останавливает остальные (возврат из Postpone, Jira-режим, автопривязка, уведомления о конце техработ) на 5 минут.
- Бот, Discord: если при создании тикета не удалось найти User ID из-за сбоя API, в тикете написано «User ID lookup failed», а не «not resolved».
- Бот: логи ModMail в Slack отправляются в фоне и больше не задерживают работу Discord-бота.
- Discord ModMail: тикет, закрытый автоматически (Scheduled Close), больше не показывается в консоли как Needs review из-за сообщения пользователя, написанного ещё до закрытия (например «ok thanks»). Needs review возвращается, только если пользователь написал после закрытия.

## Единый порядок Slack и консоли (21.11)

- **Кнопки Jira в To-Do (Forwarded, Closed, Done, Dismiss) работают одной функцией в боте и для Slack, и для консоли.** Нажатие в одном месте сразу убирает карточку в другом: Dismiss в Slack скрывает задачу в консоли и останавливает SLA-напоминание, Dismiss в консоли удаляет карточку в Slack. Если двое нажимают одновременно (Slack и консоль или две консоли), комментарий в Jira и перевод в Done выполняются один раз, второй получает «Already done by someone else». Правило «не писать "Передано", если последним написал пользователь» теперь действует и в консоли. Карточка «stuck 5 days» тоже удаляется при закрытии из консоли.
- Кнопки в консоли и Slack подписаны по-английски: Forwarded, Closed, No reply, closed. Тексты комментариев в Jira остались прежними («Передано», «Передано, закрыто», «Ответа нет, закрыто»).
- Отчёты (Community и Weekly), предложения и wishlist из Slack и консоли идут через одни функции. Отчёт из Slack теперь сохраняется и виден в консоли (Reports), поля и подписи как в консоли. Игра в wishlist из консоли теперь увеличивает общий счётчик и пишет в канал wishlist, как из Slack.
- Testing session: Slack и консоль сохраняют сессии одной функцией с одинаковыми проверками. **В консоли можно править свою сессию:** My Activity → Testing sessions → Edit (админ может править любую).
- Техработы: удалён тип доставки Email (письмо через внешний бот). Подписка на конец техработ из Slack и консоли идёт одной функцией, и Slack тоже оставляет внутреннюю заметку в чате. Команда `!maintenance` в Discord понимает Brazil-техработы.
- Discord: ответ из консоли запускает тот же Jira-цикл, что `!say` (ожидание ответа пользователя 5 дней). Привязка Jira к Discord-тикету из консоли выбирает основной тикет атомарно (двое одновременно не делают оба основными), URG-тикет никогда не становится основным (и в `!jira` тоже), повторная привязка того же ключа не дублирует заметку в Discord.
- Reddit: привязка Jira к чату из Slack пишет то же, что консоль, и ничего не делает на Reddit.

## Админка и консоль (21.11)

- Account: кнопка Change password. Notification settings: Disconnect для Telegram и Turn off для push на всех устройствах.
- Admin → Data → **Database maintenance**: отчёт по всем коллекциям базы (число записей, размер, последняя запись, записи с email, коллекции, которых нет в коде) и пронумерованные шаги обслуживания базы. Шаги, которые удаляют данные, сначала показывают цифры (Preview) и выполняются только по Apply: удалить неиспользуемые коллекции `posts` и `jira_tracked_users`, перенести оставшиеся картинки Game Cards и Telegram в отдельное хранилище.
- «Remove all emails» дополнительно убирает адреса из старых Discord-тикетов (поле Email/Session и сохранённая переписка: адрес превращается в User ID или стирается) и данные форм из завершённых действий создания тикетов. Бот теперь сам стирает данные формы и файлы из очереди сразу после создания тикета.
- Убран демо-режим. Если сервер недоступен, консоль показывает «Cannot reach the console server» и повторяет попытку, а не подставляет выдуманные данные и не делает вид, что действие выполнено.
- Наши аккаунты Jira и Reddit берутся только из Identity в профилях (и списка Reddit ignored accounts). Скрытые отдельные списки удалены.
- Удалены неиспользуемые части: старая вкладка Jira с кнопкой New, Move to Brazil, Reddit-подключение аккаунта, Maintenance Email.
- После F5 при медленной загрузке Inbox больше не показывает нули и задачу «Check the Facebook group / Never checked», пока данные ещё не пришли: до конца первой загрузки на месте списков скелетон, а счётчики скрыты (в Inbox и в заголовках разделов).
- Единые коллекции без копий:
  - **Jira-тикеты** бота и консоли теперь в одной коллекции `jira_tickets` (раньше было две: `jira_tickets` и `console_jira_tickets`). Старые записи консоли переносятся автоматически при запуске консоли (шаг 4), старую коллекцию можно удалить в Admin → Data (шаг 16).
  - **Теги** из Slack и консоли записываются в `issues` по одной схеме: у каждой записи есть чат, к которому она относится. Старые Slack-теги получают чат автоматически (шаг 5). Тег, поставленный в Slack, теперь можно убрать из консоли. Ежедневный отчёт считает теги как раньше.
  - **Ежедневный отчёт по платформам** считает Discord по упоминаниям и постам форума, которые хранит консоль, а Facebook по постам из расширения. Отдельные счётчики `discord_notifications` и `seen_facebook_posts` больше не нужны (удаляются шагами 14 и 15).
- Убран вебхук rss.app для Facebook: посты группы собирает расширение.
- Быстрее первая загрузка после F5: консоль больше не ждёт общий запрос версий `/poll` (на проде он занимал около 13 секунд на холодном кэше), а сразу и параллельно грузит все списки. Версии для фонового обновления берутся из ответов самих списков, поэтому после загрузки ничего не скачивается повторно. Добавлен индекс для сортировки постов Discord-форума.
- Перед «Remove all emails» бот дополнительно ищет User ID через облачный API там, где раньше не искал: у авторов Facebook, для которых сохранён только список адресов, и в старых Discord-тикетах, где в ответе формы остался адрес. Найденное становится «User ID N» (в тикете и в сохранённой переписке), адрес из файла Ромы проверяется без запроса. Preview показывает, сколько ещё ждёт проверки: нажимать Remove, когда там 0.

- «Apply migration» в панели User IDs from files после переноса по файлам запускает в боте досмотр всего, что осталось (адреса справочника, списки адресов Facebook, старые Discord-тикеты) через облачный API, около 40 проверок в минуту. Ход проверки виден в панели и обновляется сам.

## Емейлы больше не хранятся (этап B, после «Remove all emails»)

- Удалены шифрование адресов (ключ `EMAIL_ENC_KEY` больше не нужен ни боту, ни консоли), карта «email -> User ID» из файлов и фоновая миграция адресов в User ID.
- Admin → Data: панель «User IDs from files» убрана (загрузка файлов, миграция, проверка записей, выгрузка найденного, очистка всех адресов).
- Адрес, который присылает пользователь или вводит модератор, по-прежнему превращается в User ID через облачный API, но нигде не сохраняется: бот помнит ответ только в памяти несколько часов.
- Карточки Discord и Slack показывают User ID или «No User ID on file», строки «Email: ...» больше не бывает.
- Поиск в консоли по емейлу убран (в базе адресов нет).
